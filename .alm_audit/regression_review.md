# ALM Refactor Regression Audit (April–May 2026)

Audit window: 16 commits between `ee813a4b9` (2026-04-21) and `382d7a082` (2026-05-07) on branch `surrogate-confinement-v2` of `simsopt-surrogate`.

Audit performed against `examples/single_stage_optimization/alm_utils.py` and supporting plan docs:

- `docs/alm_minimize_impl_decomposition_plan_2026-05-07.md` (Phase 0–Final decomposition contract).
- `docs/alm_backlog5_structural_debt_plan_2026-05-07.md` (`minimize_alm` 32-line shim, helper extraction contract).
- `docs/alm_hardening_engineering_followup_todo_2026-05-07.md` (TODO 1–4 + Backlog 5 advisories).
- `docs/alm_hardening_closeout_todo_plan_2026-05-07.md` (P0–P5 closeout checklist).

## Executive Summary

The 16-commit run executes a deliberate, plan-driven decomposition of the ALM driver. Across the window I found:

- **Zero behaviour-changing diffs in any "refactor:" commit.** Every refactor commit either matches an explicit decomposition plan, is locked by direct-helper or characterization tests, or is a pure SSOT/dedupe move. No silent control-flow drift was found.
- **Three "fix:" / "perf:" commits widen behaviour intentionally** (`70cb9770c` callback contract, `cc5ed50f2` history truncation, `451d7ab09` deferred diagnostics). All three update tests and downstream callers to match the new contract. None are silent regressions, but the `70cb9770c` callback widening creates a *latent contract surface* that the live `single_stage_banana_example` caller exercises — see Smoking Gun candidate notes below.
- **`fb1d6d0d5`** removes the entire block-penalty machinery as a deliberate (schema-version-bumped) deletion. All consumers of `block_penalty_*` were swept out of the tree. This is a delete, not a refactor, and it was correctly tagged `perf:` plus a schema-version bump.
- **`80e518337`** explicitly hardens dispatch arms with `AssertionError` guards. Before this commit, `_run_alm_outer_iteration` and `_minimize_alm_impl` could silently fall through if a future enum value was added. After this commit they cannot. **The hardening is one-way: it tightens, never loosens.** Verified.
- **`382d7a082`** does *not* merely pin tuple length: each test asserts the **exact reason string** for all four `_classify_infeasible_inner_stall` arms and adds a `fail_minimize` stub that **directly proves** the inner solver is bypassed on the skipped-inner shortcut. Refactor freedom is therefore bounded.
- One **structural risk** I want flagged for author attention is in `e5819cc0e`: the simplified `_grow_continuation_trust_radius` relies on a CLI-only validation gate to guarantee `trust_radius_grow > 1`. Programmatic `ALMSettings(trust_radius_grow=0.5)` would now shrink rather than grow the trust radius silently. Low-priority but worth a `__post_init__` guard.

The audit covers `examples/single_stage_optimization/alm_utils.py` only (the request scope). Supporting test/test-fixture diffs were sampled to confirm the locks claimed by each plan.

## Smoking Gun Candidate (medium severity)

`70cb9770c perf: tighten ALM copy discipline` — callback contract widening.

In this commit, `_emit_history_snapshot` changed from passing a defensive copy (`[dict(entry) for entry in history]`) to passing the live `history` list reference. The commit message claims a contract: *"Callback contract: history is borrowed/read-only ALM state."* The accompanying test asserts `assertIs(history_snapshots[-1]["history"], result.history)` and that mutations through `latest_entry` (which is still snapshotted) do not bleed into `result.history`.

**The smoking-gun shape**: a *later* commit (`f498321db`, 2026-04-26 21:59) added a callback in `examples/single_stage_optimization/SINGLE_STAGE/single_stage_banana_example.py:9020` that **mutates** the borrowed `history`:

```python
def history_callback(history, latest_history_entry, multipliers, penalty):
    alm_partial_state["history"] = history
    update_single_stage_alm_smoothing_from_history(latest_history_entry)
    if history:
        history[-1]["smoothing_changed"] = latest_history_entry["smoothing_changed"]
```

The `history[-1]["smoothing_changed"] = ...` line mutates the live ALM history through the borrowed reference. After `70cb9770c` this is an in-place mutation of `result.history[-1]`. Because the field is appended (not overwritten by the ALM driver), this is currently *additive* — no schema field is being clobbered. **But the borrow-vs-own contract documented in the commit comment is being directly violated by a downstream caller**, and the snapshot path's deepcopy in `_snapshot_history_entry` (added later) does not protect the live history list.

This is not a numeric regression (no math diverges, no termination string changes). It is a **contract-discipline regression**: the ALM module published a "history is read-only" comment, and a downstream caller writes through it. Recommend either:

- Tighten the contract: re-add the defensive copy at `_emit_alm_history_snapshot` boundary and update the test that asserts `assertIs(history, result.history)` — or —
- Document the existing pattern: change the comment to "history is the live ALM history list; in-place mutation is allowed for additive keys".

Either path resolves the latent contract drift. The current state works because no field collision exists, but is one well-meaning future caller away from a silent `result.history` corruption.

## Audit Hazard Checklist (per request)

1. **Helper extraction with mutated args.** No mutation drift found. The `_handle_alm_dual_update_transition` extraction returns a frozen `_ALMDualUpdateResult`; the caller copies fields out and mutates `history_entry` and `cap_binding_*` exactly as before. The `_ContinuationStepState` carrier in `a31a3e9f4` is intentionally mutable, owned by one continuation-step call, and never escapes scope.
2. **Exception swallowing.** No `except Exception:` or `except (...)` was introduced inside any extracted helper. Verified via `git grep -nE "except.*:" examples/single_stage_optimization/alm_utils.py` and `git show <sha> -- alm_utils.py | grep "+except"` for each commit.
3. **Default-value drift in `_ALMContinuationStepResult`.** None — the dataclass shape is identical pre/post `a31a3e9f4`. AST comparison: 14 fields, all required, no defaults.
4. **Dispatch arm coverage.** Soft in `52ff64d7f`, hardened in `80e518337` with `AssertionError` for unhandled enum values. All five enum members (`RETURN`/`BREAK_OUTER`/`CONTINUE_CONTINUATION` for continuation; `RETURN`/`NEXT_OUTER`/`EXHAUST` for outer) are now dispatched.
5. **Order of operations (history append vs penalty bump vs dual update).** Verified in `92594bf99` and `a31a3e9f4`: every emit-snapshot site is preceded by `_attach_alm_history_diagnostics`; penalty-increase always mutates `state.penalty` and `run_state.penalty_cap_*` *before* the cap-result return; dual-update tightens tolerances *after* projecting multipliers. No reordering observed.
6. **Removed code that wasn't dead.** `normalized_quadratic_penalty_residual` and `normalized_lp_penalty_residual` were verified unused in `80e518337~1` via `git grep` across `examples/`, `tests/`, and notebooks (only their own tests referenced them; the deletion test removed those tests too).
7. **Stall classification semantics.** `382d7a082` pins the **reason string** for each of the four arms (not just tuple shape) and adds a `fail_minimize` stub that raises if SciPy `minimize` is invoked on the skipped-inner shortcut path. Bound, not loose.
8. **Cache invalidation.** `273fba661`'s `MappingProxyType` hardens the `ALMBlockPenaltyState` mappings so the cached `penalty_vector` cannot go stale via dict mutation. The only path to a new vector is constructing a new (frozen) state, which recomputes in `__post_init__`. After `fb1d6d0d5` the entire block-penalty cache is removed; the surviving `_positive_shift_and_augmented_terms` cache lives on the per-evaluation dict and has a one-evaluation lifetime, so cross-call staleness is not possible. Frontier-evaluator cache key derivation is unchanged.

## Recommended Follow-ups

1. **Resolve the `70cb9770c` borrow-vs-own contract** before another caller adds a non-additive write through the borrowed history list. Either restore the defensive copy or update the contract comment to permit additive in-place mutation.
2. **Add an `__post_init__` guard for `ALMSettings.trust_radius_grow`** (must be `> 1.0`). The CLI-only validation surface from `e5819cc0e` leaves a programmatic-construction hole. One-line addition.
3. **Optional**: capture the `_ContinuationStepState` mutation discipline in a property-style test (e.g. assert that `_finalize_continuation_step` reads every carrier field), to harden against the carrier-write-omission risk class introduced by `a31a3e9f4`. Current arm tests cover behaviour but not the carrier invariant directly.

None of the three follow-ups block merge; the codebase passes all 391 ALM-tagged tests per the `e5819cc0e` and `a31a3e9f4` validation evidence.
